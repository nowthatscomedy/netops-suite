# 데이터 및 보안 가이드

## 목적 {#data-security}

NetOps Suite가 다루는 자격 증명, 네트워크 정보, 구성, 로그, AI 첨부와 암호화 키를 안전하게 입력·저장·공유·폐기하기 위한 기본 원칙을 설명합니다.

## 사전 준비 및 권한

- 조직의 정보 분류, 비밀 관리, 로그 보존, 외부 AI 사용과 네트워크 스캔 정책을 확인합니다.
- 저장 폴더는 업무상 필요한 사용자만 접근하도록 Windows NTFS 권한을 제한합니다.
- 장비 목록·백업·CLI·로그의 보관 기간과 책임자를 정합니다.
- 파일 전송 서버 또는 장비 점검을 시작하기 전에 대상·계정·영향과 작업 승인 기록을 준비합니다.
- 앱의 관리자 권한은 시스템 변경 시에만 사용합니다.

## 입력 및 선택 사항

다음 데이터는 민감 정보로 분류해 취급합니다.

| 데이터 | 포함될 수 있는 정보 | 대표 위치 |
| --- | --- | --- |
| 장비 목록 Excel | IP, 계정, 비밀번호, enable 비밀번호 | 사용자가 선택한 파일 |
| 점검 산출물 | 구성, 명령 출력, 오류, 장비 식별 정보 | `inspector\runs` |
| 생성 CLI | 내부 주소, VLAN, SNMP/로컬 계정 값 | 결과/내보내기 또는 선택 경로 |
| 전송·진단 로그 | 호스트, 사용자명, 경로, 포트, 파일명 | 로그/내보내기 폴더 |
| AI 대화·첨부 | 프롬프트, 파일 내용, 내부 네트워크 문맥 | 제공자 및 `.md` 내보내기 |
| FTPS·SFTP·SCP 키 | 서버 인증서 개인 키, SSH 호스트 개인 키 | 현재 설정 폴더의 FTP 키 디렉터리 |

- `설정 > 저장 위치`에서 설정, 로그, 결과 폴더를 분리할 수 있습니다.
- 파일 전송 서버는 바인드 IP, 읽기 전용 여부와 익명 접속 여부를 선택합니다.
- Codex는 읽기 전용, 작업공간 액세스, 전체 액세스 권한을 선택할 수 있습니다.

## 사용 방법

### 입력 전

1. 실제 비밀번호 대신 비밀 관리 체계에서 작업용 자격 증명을 발급받습니다.
2. 최소 권한의 읽기 전용 또는 제한 계정을 우선 사용합니다.
3. 문서·샘플·테스트에는 `192.0.2.0/24`, `.example.test`, `CHANGE_ME_PASSWORD` 같은 가상 값을 사용합니다.
4. 장비 Excel을 암호화할 수 있다면 승인된 방식으로 암호화하고, 파일 암호는 다른 채널로 관리합니다.

### 실행 중

1. 변경 확인 창에서 대상, 영향, 되돌리기 방법과 출력 위치를 다시 확인합니다.
2. 임시 서버는 특정 인터페이스 IP와 읽기 전용으로 제한하고 필요한 시간만 실행합니다.
3. SFTP/SCP 호스트 키와 FTPS 인증서 지문을 별도 신뢰 채널의 값과 비교합니다.
4. AI 요청에는 필요한 최소 문맥만 첨부하고 비밀번호, 토큰, 개인 키, 전체 구성 백업을 보내지 않습니다.
5. 로그 화면을 공유할 때는 내부 주소, 사용자명, 파일 경로와 명령 출력을 가립니다.

### 실행 후

1. 장비별 성공·실패와 실제 변경 내용을 검증합니다.
2. 임시 서버, 연속 진단과 iperf3 서버를 중지합니다.
3. 결과 파일을 승인된 보관소로 이동하고 로컬 임시 사본을 조직 정책에 따라 정리합니다.
4. 불필요해진 작업용 비밀번호와 토큰을 회수·교체합니다.
5. FTPS/SFTP/SCP 서버 키가 노출됐으면 키를 교체하고 새 지문을 배포합니다.

## 성공 확인

- 설정·로그·결과 폴더가 승인된 절대 경로를 가리키고 권한이 제한되어 있습니다.
- 장비 목록과 산출물에 자리표시자 또는 승인된 작업용 비밀만 사용했습니다.
- 모든 임시 서버와 장기 실행 작업이 종료됐습니다.
- 내보낸 자료의 보관 위치, 소유자와 폐기 시점이 정해졌습니다.
- AI 제공자로 보내진 데이터와 감사 로그를 검토할 수 있습니다.
- 서버 지문과 인증서 지문을 신뢰 채널을 통해 확인했습니다.

## 결과 및 저장 위치

- 기본 데이터 루트는 `%LOCALAPPDATA%\NetOps Suite`입니다.
- 정확한 설정·로그·결과 경로는 `설정 > 저장 위치`에서 확인합니다.
- 장비 점검 산출물은 데이터 루트의 `inspector\runs`, CLI 사용자 프로파일은 `config_builder`, 사용자 점검 규칙은 `inspector`에 저장될 수 있습니다.
- AI 도구 감사 기록은 로그 폴더의 `netops_assistant_audit.jsonl`, 앱 로그는 `app.log`입니다.
- 수동 저장 파일과 다운로드 파일은 사용자가 저장 대화상자 또는 로컬 폴더에서 선택한 위치에 저장됩니다.
- `모든 설정 초기화`는 기존 로그·결과·백업·내보낸 파일을 삭제하지 않습니다. 별도 보존·폐기 절차가 필요합니다.

## 주의사항

- UI에서 비밀번호가 점으로 보이는 것과 디스크 파일이 암호화되는 것은 다릅니다.
- FTP·TFTP·Telnet은 통신 보호가 부족합니다. 호환성 때문에 불가피한 격리망에서만 사용합니다.
- 앱이 표시한 SFTP/SCP 지문은 연결 후 얻은 값일 수 있습니다. 미리 받은 값과 비교하지 않으면 서버 신원을 보장하지 못합니다.
- 자체 서명 FTPS 인증서는 지문 확인 없이는 신뢰 근거가 되지 않습니다.
- 결과 파일을 이메일, 메신저, 개인 클라우드 또는 외부 AI에 올리기 전에 조직의 반출 승인을 확인합니다.
- 폴더 경로를 네트워크 공유나 동기화 폴더로 바꾸면 데이터 복제 범위가 넓어집니다.
- 앱 설정 초기화는 Windows 네트워크 설정, 원격 장비 변경과 외부 제공자 데이터를 되돌리지 않습니다.

## 문제 해결

- 민감 파일 위치를 모르겠으면 `설정 > 저장 위치`, 장비 점검의 `폴더 열기`, 최근 저장 완료 메시지를 확인합니다.
- 비밀번호가 로그나 결과에 노출됐으면 파일 접근을 즉시 제한하고 해당 비밀번호를 교체한 뒤 공유 사본을 회수합니다.
- 서버 키가 유출됐거나 지문이 예고 없이 바뀌면 서버를 중지하고 키 파일·배포 경로를 조사한 뒤 새 키를 발급합니다.
- 승인되지 않은 외부 AI 전송이 의심되면 요청을 중지하고 제공자·조직의 사고 대응 절차에 따라 대화·감사 기록을 보존합니다.
- 모든 설정 초기화 후에도 민감 결과가 남아 있으면 결과·로그 폴더를 직접 검토해 조직의 안전한 삭제 절차를 적용합니다.
