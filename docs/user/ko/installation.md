# 설치, 실행 및 업데이트

## 목적 {#installation}

공식 Windows 설치본 또는 소스 개발 환경에서 NetOps Suite를 안전하게 설치·실행하고, 업데이트 설치 파일의 무결성과 게시자 정보를 확인하는 방법을 설명합니다.

## 사전 준비 및 권한

- 64비트 Windows 10 버전 1809(빌드 17763) 이상이 필요합니다.
- 공식 설치 프로그램은 시스템 설치를 위해 Windows 관리자 승인을 요청합니다.
- 소스 실행은 Python 3이 필요하며 프로젝트의 고정 개발 의존성을 설치할 수 있어야 합니다.
- 설치·의존성 설치·업데이트 확인에는 인터넷 연결이 필요할 수 있습니다.
- 조직 보안 정책에서 GitHub Releases, Python 패키지 설치 또는 `winget` 사용이 허용되는지 확인합니다.

## 입력 및 선택 사항

- 공식 설치 파일 이름은 `NetOpsSuite-setup-<버전>.exe` 형식입니다.
- 설치 마법사에서 바탕 화면 바로가기 생성 여부를 선택할 수 있습니다.
- 개발 실행은 기본 사용자 데이터 경로 또는 프로젝트 데이터 경로 중 하나를 선택합니다.
- 업데이트 자동 확인은 `설정 > 프로그램 > 프로그램 시작 시 업데이트 확인`에서 켜거나 끕니다.
- 등록된 기본 Program Files 설치를 상위 버전으로 업데이트하면 설치 프로그램이 기존 실행 파일과 앱 번들 폴더(`_internal`)를 함께 임시 백업한 뒤 새 버전으로 다시 구성합니다.

## 사용 방법

### 공식 설치본

1. 공식 `nowthatscomedy/netops-suite` GitHub Releases에서 설치 파일을 받습니다.
2. 파일 이름이 `NetOpsSuite-setup-<버전>.exe` 형식인지 확인합니다.
3. 설치 파일의 Windows 디지털 서명과 게시자 정보를 확인합니다. SHA-256 일치는 전송 중 변조 여부를 확인할 뿐 게시자 신뢰를 대신하지 않습니다.
4. 기존 설치를 업데이트한다면 실행 중인 NetOps Suite를 먼저 종료합니다. 앱 파일이 잠겨 있으면 설치 프로그램은 기존 파일을 덮지 않고 중단되므로 앱을 닫은 뒤 다시 실행합니다.
5. 설치 프로그램을 실행하고 관리자 승인 창을 확인합니다.
6. 시작 메뉴 또는 선택한 바탕 화면 바로가기에서 `NetOps Suite`를 실행합니다.

### 소스 개발 환경

프로젝트 루트의 PowerShell에서 다음을 실행합니다.

```powershell
.\scripts\install_dev.ps1
.\scripts\run_dev.ps1
```

가상 환경을 만든 뒤에는 `run_netops_suite.bat`로도 실행할 수 있습니다. 소스 실행은 설정·결과·로그를 프로젝트 폴더의 `data` 폴더 하나에 저장합니다.

### 앱 내부 업데이트

1. `설정 > 프로그램`을 엽니다.
2. `업데이트 확인`을 누릅니다.
3. 새 버전이 있으면 버전과 릴리스 정보를 확인하고 다운로드를 승인합니다.
4. 앱이 다운로드 파일의 SHA-256과 설치 파일 정보를 검증할 때까지 기다립니다.
5. Windows 코드 서명과 게시자를 다시 확인한 뒤 설치 프로그램 실행을 승인합니다. 실행을 승인하면 현재 앱이 종료됩니다.
6. 설치 프로그램이 기존 실행 파일과 앱 번들을 백업하고 새 파일을 복사할 때까지 기다린 뒤 NetOps Suite를 다시 실행합니다. 설치가 정상 완료된 경우에만 이전 백업 제거를 시도하며, 제거하지 못한 백업은 다음 설치에서 복구·정리를 시도합니다.

## 성공 확인

- 창 제목이 `NetOps Suite`로 표시되고 시작 화면과 작업별 왼쪽 메뉴가 보입니다.
- 하단 상태 표시줄에 현재 버전과 `준비` 상태가 표시됩니다.
- `설정 > 프로그램`의 현재 버전이 설치하려던 버전과 일치합니다.
- 개발 실행이라면 `.venv\Scripts\python.exe`가 사용되고 앱이 오류 코드 없이 시작됩니다.

## 결과 및 저장 위치

- 공식 설치 기본 폴더는 Windows의 64비트 프로그램 폴더 아래 `NetOps Suite`입니다.
- 사용자 설정과 실행 데이터는 데이터 폴더 하나에 저장됩니다. 설치본은 `%LOCALAPPDATA%\NetOps Suite`, 설치 없이 실행하면(소스 실행 또는 압축을 푼 실행 파일) 프로그램 폴더의 `data` 폴더가 데이터 폴더입니다.
- 설치 없이 쓰려면 소스 폴더에서 `run_netops_suite.bat`을 실행합니다. 설정·결과·로그가 모두 `data` 폴더에 저장되므로 폴더째 옮겨 쓸 수 있습니다.
- 설치 없이 처음 실행할 때 `data` 폴더가 비어 있고 이 PC에 설치본 데이터가 있으면 설치본의 설정과 사용자 프로파일을 복사해 옵니다. 기존 결과 파일은 복사하지 않습니다.
- 기본 설치 폴더의 실행 파일과 `_internal`은 업데이트 때 같은 버전의 페이로드로 다시 구성됩니다. 설치가 중단되면 임시 백업에서 두 항목의 이전 세대 복구를 시도하며, 다음 설치 실행에서도 중단된 백업을 확인합니다. 복구에 실패한 백업은 설치 폴더에 남을 수 있습니다.
- `%LOCALAPPDATA%\NetOps Suite`의 설정, 로그, 결과, 백업과 사용자 프로파일 및 설치 폴더 루트의 알 수 없는 파일은 앱 번들 정리 대상이 아닙니다. 다만 새 배포본과 같은 이름의 루트 파일은 정상 설치 과정에서 덮어쓸 수 있습니다.
- 업데이트 설치 파일은 검증 후 앱이 안내한 다운로드 경로에 남을 수 있습니다.
- 이전 버전이 `logs\exports`, `inspector\runs`, `config_builder\outputs`에 저장한 결과는 첫 실행 때 `results`로 옮겨집니다. 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 원래 위치에 남깁니다.
- 제거된 AI 기능이 남긴 모델 목록 캐시(`config\ai_model_catalog_cache.json`)는 첫 실행 때 삭제됩니다. 설정, 프로파일, 결과, 로그는 삭제하지 않습니다.

## 주의사항

- 출처가 불분명하거나 이름만 비슷한 설치 파일을 실행하지 마세요.
- SHA-256 검증 성공만으로 코드 서명을 대신할 수 없습니다. 설치 전에 Windows의 디지털 서명 탭을 별도로 확인하세요.
- 소스 개발 환경은 `requirements-dev-lock.txt`의 고정 의존성을 사용합니다. 임의로 버전을 섞으면 지원되지 않는 동작이 생길 수 있습니다.
- 앱이 실행 중일 때 업데이트 설치를 강제로 진행하면 미저장 화면 상태나 실행 중 작업이 중단될 수 있습니다.
- `_internal`은 앱 전용 폴더입니다. 이 폴더에 사용자가 임의로 넣은 파일은 상위 버전 업데이트가 성공하면 현재 `_internal`에서는 제거되지만, 이전 백업 제거가 실패하면 임시 백업에 남을 수 있습니다.
- Program Files 밖의 사용자 지정 설치 경로와, 진행 중인 신뢰 가능한 백업이 없는 정상 상태의 동일 버전 재설치에서는 자동 번들 정리를 건너뜁니다. 더 최신 버전이 설치된 상태의 다운그레이드는 혼합 런타임을 방지하기 위해 차단됩니다. 남은 앱 파일을 임의의 재귀 삭제 명령으로 지우지 마세요.

## 문제 해결

- `Python virtual environment was not found`가 나오면 프로젝트 루트에서 `.\scripts\install_dev.ps1`을 먼저 실행합니다.
- PowerShell 실행 정책 때문에 스크립트가 차단되면 조직 정책에 맞는 승인된 방법으로 스크립트를 실행해야 합니다. 정책을 임의로 완화하지 마세요.
- 설치본이 시작되지 않으면 Windows 이벤트와 `%LOCALAPPDATA%\NetOps Suite\logs\app.log`를 확인합니다.
- 업데이트 확인 또는 다운로드·무결성 검증이 실패하면 인터넷·프록시·GitHub 접근 정책을 확인하고 다시 시도합니다. 설치 프로그램을 실행하기 전 단계의 실패는 기존 설치 파일을 제거하지 않습니다.
- 설치 프로그램이 중단되어 앱이 시작되지 않으면 같은 버전 또는 최신 공식 설치 프로그램을 다시 실행합니다. 신뢰할 수 있는 임시 백업이 있으면 이전 번들 복구를 시도한 뒤 설치를 다시 진행하며 사용자 데이터 폴더는 그대로 유지됩니다. 복구가 계속 실패하면 설치 로그와 백업 폴더를 보존한 채 지원을 요청하세요.
- 설치 파일 실행 전 게시자 정보가 없거나 예상과 다르면 설치를 취소하고 공식 릴리스 출처를 다시 확인합니다.

## 설치, 실행 및 업데이트 빠른 안내 {#quick-installation}

NetOps Suite를 설치하고 실행합니다.

**준비**: 64비트 Windows 10 버전 1809 이상과 공식 설치 파일을 준비합니다.

1. 설치 파일을 실행하고 설치 위치를 확인합니다.
2. 시작 메뉴에서 NetOps Suite를 엽니다.
3. 설정에서 현재 버전과 업데이트 확인을 확인합니다.

**성공 확인**: 시작 화면이 표시되고 작업 메뉴를 열 수 있습니다.

**안 되면**: 실행이 막히면 설치 파일의 출처와 Windows 안내를 확인합니다.
