# NetOps Suite v1.2.0

`v1.2.0`은 오래된 펌웨어 장비에 SSH로 잘 접속되지 않던 문제를 고치고, 장비 점검 프로파일을 저장하기 전에 실제 장비로 시험해 볼 수 있게 한 기능 릴리스입니다. v1.1.0 설치본에는 구형 장비용 SSH 구성 요소가 빠져 있어, SHA-1이나 DSS 방식만 지원하는 장비는 접속에 실패했습니다.

## 한눈에 보기

- 구형 장비용 SSH 구성 요소를 설치 파일과 포터블 zip에 넣었습니다. `ssh-rsa`·`ssh-dss` 호스트 키나 `diffie-hellman-group1-sha1`·`group14-sha1` 키 교환만 지원하는 장비도 따로 설정하지 않고 접속합니다.
- 프로파일 만들기에 `장비로 시험` 탭을 추가했습니다. 저장하기 전에 장비 한 대에서 명령을 실행하고, 가져온 출력으로 출력 예시를 채운 뒤 Excel 컬럼에 들어갈 값을 바로 보여 줍니다.
- `SSH 방식 확인`으로 로그인하지 않고 장비가 지원하는 SSH 방식을 볼 수 있습니다.
- 장비 점검·백업·사용자 명령 실행에 `첫 장비 1대만 먼저 실행`을 추가했습니다.
- 결과 Excel의 오류 메시지 뒤에 `조치:`로 다음에 할 일을 안내합니다.

## 이전 버전과 달라진 점

v1.1.0은 SSH 라이브러리를 Paramiko 5로 올리면서 SHA-1·DSS 알고리즘을 기본 연결에서 뺐습니다. 이런 장비는 구형 장비 호환 모드로 자동 전환해야 하는데, 그 구성 요소가 설치본에 없어 `레거시 SSH 런타임이 없습니다` 오류로 끝났습니다. 이번 버전은 호환 구성 요소를 설치 폴더의 `_internal\legacy_ssh`에 함께 넣고, 구형 장비에 접속할 때만 별도 프로세스에서 불러옵니다. 앱 본체는 계속 Paramiko 5를 사용합니다.

한 번 호환 모드로 접속된 장비는 프로그램을 끌 때까지 처음부터 호환 모드로 접속합니다. 짧은 시간에 접속을 여러 번 시도하면 막아 버리는 장비에서 실패가 줄어듭니다.

## 새 기능

- `장비로 시험`: 프로파일 만들기에서 장비 IP·계정·비밀번호를 입력하고 `시험 실행`을 누르면, 저장했을 때와 같은 접속 방식으로 점검·백업 명령을 한 번 실행합니다. 계정과 비밀번호는 저장하지 않고, 세션 로그는 결과 폴더의 `session_logs`에 남습니다.
- `SSH 방식 확인`: 장비가 제공하는 키 교환·호스트 키·암호화·무결성 방식을 읽어 기본 SSH로 접속되는지, 호환 모드가 필요한지, 지원하지 않는 장비인지 알려 줍니다.
- `첫 장비 1대만 먼저 실행`: 장비 목록의 첫 장비에서만 실행해 결과를 확인한 뒤 전체를 실행할 수 있습니다.

## 개선 및 수정

- 접속 실패 메시지에 TCP 연결 실패, SSH 응답 지연·동시 접속 초과, SSH 방식 불일치, 인증 실패, 호스트 키 불일치, 프롬프트 인식 실패별 조치 안내를 붙였습니다.
- 릴리스 빌드가 포함된 구형 SSH 구성 요소를 패키지 실행 파일로 직접 점검하고, 실패하면 빌드를 중단합니다.
- 장비 점검 도움말의 구형 장비 SSH, 프로파일 만들기, 문제 해결 내용을 새 기능에 맞게 고치고 화면 캡처를 추가했습니다.

## 설치 및 주의사항

- 지원 환경은 64비트 Windows 10 버전 1809(빌드 17763) 이상입니다.
- 설치 파일은 `NetOpsSuite-setup-1.2.0.exe`, 설치 없이 쓰는 압축 파일은 `NetOpsSuite-portable-1.2.0.zip`입니다.
- 구형 장비용 구성 요소인 Paramiko 3.5.1은 SHA-1 RSA 서명을 허용한다는 이유로 `PYSEC-2026-2858` 권고에 올라 있습니다. 오래된 장비에 접속하려면 이 허용이 필요하므로 그대로 포함했고, 앱 본체가 아닌 별도 프로세스에서만 사용합니다. 장비 목록 Excel의 `legacy_ssh` 열에 `FALSE`를 넣으면 해당 장비는 호환 모드로 전환하지 않습니다.
- 기본 Program Files 설치 위에 실행하면 이전 실행 파일과 `_internal` 앱 번들이 새 버전으로 교체됩니다. 실행 중인 NetOps Suite를 먼저 종료하세요.
- 코드 서명 인증서가 구성되지 않은 경우 명시적으로 승인된 무서명 릴리스로 게시되며, Windows에서 확인된 게시자 정보가 표시되지 않을 수 있습니다.

## 검증 및 무결성

- 가이드 생성·검증, 정적 검사, 의존성 감사, Python 컴파일과 전체 자동화 테스트를 릴리스 워크플로에서 수행합니다.
- SHA-1·DSS만 지원하는 로컬 테스트 SSH 서버로 자동 전환, 장비로 시험, SSH 방식 확인을 검사합니다. 실제 장비 접속 시험은 포함하지 않습니다.
- 설치 업그레이드 트랜잭션 검사, 패키징된 실행 파일의 시작 검사와 구형 SSH 구성 요소 자체 점검을 통과해야 게시됩니다.
- 설치 파일, 포터블 zip과 함께 `SHA256SUMS.txt` 및 CycloneDX 형식의 `python-dependencies.cdx.json`을 게시합니다. 실제 체크섬과 서명 상태는 게시된 자산과 워크플로 결과에서 확인하세요.
