# NetOps Suite v1.4.0

`v1.4.0`은 장비 점검·백업을 많은 장비에 돌릴 때 진행과 결과를 화면에서 바로 보고, 실패한 장비만 다시 실행할 수 있게 한 기능 릴리스입니다. Excel 없이 장비 목록을 만들고, 공통 계정을 한 번만 입력하고, 백업할 때 이전 설정과 바뀐 줄을 비교할 수 있습니다. 설정 명령 만들기에서 만든 장비별 CLI를 장비 점검으로 넘겨 실행할 수도 있습니다.

## 한눈에 보기

- 실행하는 동안 진행 막대와 `12/40대 완료 (성공 10 · 실패 2)` 같은 진행 상황이 나옵니다.
- 끝나면 `n대 중 n대 성공` 요약과 장비별 결과 표가 나오고, 실패한 장비는 원인·조치와 함께 맨 위에 옵니다.
- `실패한 n대만 다시 실행` 버튼으로 실패한 장비에만 같은 작업을 다시 실행합니다.
- `표에서 만들기`로 Excel 없이 장비 목록을 만들고, `공통 계정 사용`으로 계정을 한 번만 입력합니다.
- 백업하면 장비마다 이전 백업과 비교하고 바뀐 줄을 따로 볼 수 있습니다.
- 설정 명령 만들기의 `장비 점검으로 보내기`로 장비별 CLI를 같은 IP 장비에 실행합니다.

## 이전 버전과 달라진 점

v1.3.0까지는 실행 중에 "실행 중입니다"만 보였고, 완료 메시지는 `완료: 모드 inspection / 장비 n대`처럼 내부 값을 그대로 보여 줬습니다. 몇 대가 실패했는지는 결과 Excel을 열어야 알 수 있었고, 실패한 장비만 다시 돌리려면 Excel을 새로 만들어야 했습니다.

실행 모드는 드롭다운에서 버튼 네 개(`점검`, `백업`, `점검+백업`, `명령 일괄 입력`)로 바뀌었고, `사용자 명령`은 `명령 일괄 입력`으로 이름을 바꿨습니다. 장비 점검의 프로파일은 `점검 프로파일`, 설정 명령 만들기의 프로파일은 `설정 프로파일`로 이름을 나눠 둘을 헷갈리지 않게 했습니다. 저장된 프로파일 파일과 장비 목록 Excel 형식은 바뀌지 않았습니다.

## 새 기능

- 장비별 결과 표: IP, 장비 종류, 성공·실패와 오류 원인·`조치:` 안내를 화면에서 바로 확인합니다.
- 실패한 장비만 다시 실행: 같은 작업과 설정으로 실패한 IP에만 다시 접속하고 새 결과 Excel을 만듭니다.
- 표에서 장비 목록 만들기·편집: IP 목록을 붙여넣으면 행이 늘어나고, 잘못된 IP·겹치는 IP·빈 필수 칸을 바로 표시합니다. 비밀번호 칸은 점으로 가려 보입니다.
- 공통 계정: Excel의 빈 계정·비밀번호·enable 비밀번호 칸에만 적용되며 파일에 저장하지 않습니다.
- 백업 비교: 같은 장비의 바로 이전 백업과 비교해 `변경됨`, `이전과 같음`, `첫 백업`을 표시하고, 백업할 때마다 바뀌는 시각 줄은 빼고 비교합니다.
- 장비 점검으로 보내기: 설정 명령 만들기에서 관리 IP 열을 골라 장비별 CLI를 넘기면, 장비 점검이 같은 IP 장비에만 각자의 CLI를 실행합니다. 처음에는 `첫 장비 1대만 먼저 실행`이 켜집니다.
- 점검 프로파일 시험에서 고른 장비 목록의 장비를 골라 IP·계정·접속 방식을 채웁니다.
- 프로파일이 없는 장비 종류 때문에 검증이 실패하면 그 벤더·OS가 채워진 점검 프로파일 만들기 버튼이 나옵니다.

## 개선 및 수정

- 연결 진단·파일 전송·설정 화면의 로그 줄마다 `[시:분:초]` 시각을 붙였습니다.
- 장비 점검의 `장비 목록 Excel` 이름이 두 번 보이던 문제를 고쳤습니다.
- 장비 점검·설정 명령 만들기·데이터 보안 도움말과 화면 캡처를 새 화면에 맞게 고쳤습니다.

## 설치 및 주의사항

- 지원 환경은 64비트 Windows 10 버전 1809(빌드 17763) 이상입니다.
- 설치 파일은 `NetOpsSuite-setup-1.4.0.exe`, 설치 없이 쓰는 압축 파일은 `NetOpsSuite-portable-1.4.0.zip`입니다.
- 기본 Program Files 설치 위에 실행하면 이전 실행 파일과 `_internal` 앱 번들이 새 버전으로 교체됩니다. 실행 중인 NetOps Suite를 먼저 종료하세요.
- `장비 점검으로 보내기`로 넘긴 CLI는 설정을 바꾸는 명령입니다. 변경 승인 후 먼저 백업하고 한 대에서 확인한 뒤 전체를 실행하세요.
- 코드 서명 인증서가 구성되지 않은 경우 명시적으로 승인된 무서명 릴리스로 게시되며, Windows에서 확인된 게시자 정보가 표시되지 않을 수 있습니다.

## 검증 및 무결성

- 가이드 생성·검증, 정적 검사, 의존성 감사, Python 컴파일과 전체 자동화 테스트를 릴리스 워크플로에서 수행합니다.
- 실패 장비 재실행, 공통 계정 적용, 장비별 CLI 실행, 백업 비교, 장비 목록 표 편집을 자동화 테스트로 검사하고, 오프스크린 화면 검사로 1024×680·1280×800·1600×900 창과 125%·150% 배율 배치를 확인했습니다. 실제 장비 접속 시험은 포함하지 않습니다.
- 설치 파일, 포터블 zip과 함께 `SHA256SUMS.txt` 및 CycloneDX 형식의 `python-dependencies.cdx.json`을 게시합니다. 실제 체크섬과 서명 상태는 게시된 자산과 워크플로 결과에서 확인하세요.
