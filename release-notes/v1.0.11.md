# NetOps Suite v1.0.11

`v1.0.11`은 버전 업데이트 뒤 설치 폴더에 남을 수 있던 이전 PyInstaller 런타임 파일을 안전하게 정리하는 유지보수 릴리스입니다. 설치 폴더 전체를 지우지 않고 NetOps Suite 실행 파일과 `_internal` 번들을 하나의 트랜잭션으로 교체하며, 사용자 설정·로그·결과와 설치 폴더 루트의 알 수 없는 파일은 정리하지 않습니다.

## 한눈에 보기

- 기본 Program Files 설치를 상위 버전으로 업데이트할 때 실행 파일과 이전 `_internal` 앱 번들을 같은 새 버전으로 정확히 교체합니다.
- 기존 실행 파일과 번들은 먼저 같은 설치 폴더에 임시 백업되며, 새 설치가 성공한 경우에만 제거를 시도합니다.
- 설치 실패나 취소 시 이전 번들 복구를 시도하고, 정전 등으로 남은 신뢰 가능한 백업은 다음 설치에서 복구·정리를 다시 시도합니다.
- `%LOCALAPPDATA%\NetOps Suite`의 사용자 데이터와 설치 폴더 루트의 수동 `iperf3.exe`처럼 새 배포본과 이름이 겹치지 않는 사용자 파일은 정리 루틴이 삭제하지 않습니다.
- 등록된 설치 경로, 버전, 재분석 지점과 백업 표식을 확인해 정리 범위를 제한합니다.

## 이전 버전과 달라진 점

이전 버전은 동일한 설치 경로에 새 파일을 덮어썼기 때문에 새 번들에서 제거된 라이브러리나 리소스가 `_internal`에 남을 수 있었습니다. 이번 버전은 동일 AppId로 등록된 기본 Program Files 설치이고 설치하려는 버전이 더 높을 때만 기존 실행 파일과 `_internal`을 별도 백업 이름으로 이동한 후 새 페이로드를 설치합니다. 진행 중인 신뢰 가능한 백업이 없는 정상 상태의 동일 버전 재설치, 등록 정보가 일치하지 않는 폴더와 Program Files 밖의 사용자 지정 경로에서는 파괴적인 정리를 수행하지 않으며, 다운그레이드는 혼합 런타임을 방지하기 위해 설치 전에 차단합니다.

## 새 기능

- 설치 프로그램에 앱 실행 파일과 런타임을 함께 보호하는 백업·커밋·복구 흐름을 추가했습니다.
- 설치 도중 중단된 백업을 식별하는 전용 표식을 기록하고, 다음 실행에서 AppId와 설치 경로가 정확히 일치할 때만 복구합니다.
- 설치 성공 시 이전 번들만 제거를 시도하고, 실패하거나 사용자가 취소하면 새로 복사되던 번들을 제거한 뒤 이전 번들을 원래 위치로 되돌리려고 시도합니다. 즉시 복구하지 못한 백업은 다음 설치에서 다시 확인합니다.

## 개선 및 수정

- 설치 폴더 전체나 와일드카드를 삭제하지 않고 정확한 `{app}\NetOpsSuite.exe`와 `{app}\_internal` 관리 경계만 교체합니다.
- 기존 제거 등록의 `InstallLocation`과 `DisplayVersion`, 설치 실행 파일을 확인해 신규 설치 폴더의 동명 디렉터리를 잘못 정리하지 않도록 했습니다.
- 정식·시험 버전의 SemVer 우선순위를 비교해 상위 버전에서만 정리하고, 더 오래된 설치 파일로 다운그레이드하는 흐름은 차단합니다.
- 설치 경로와 백업 경로의 상위 요소에서 NTFS 재분석 지점을 확인하고 안전하지 않은 리디렉션이 발견되면 정리를 거부합니다.
- Inno Setup의 `RedirectionGuard`와 실행 중 파일 감지를 명시적으로 활성화했습니다.
- 설치 폴더 루트의 알 수 없는 파일, 수동 도구, 제거 프로그램 파일 및 `%LOCALAPPDATA%` 사용자 데이터는 정리 대상에서 제외했습니다. 단, 새 배포본과 이름이 같은 루트 파일은 정상 설치 과정에서 덮어쓸 수 있습니다.

## 설치 및 주의사항

- 지원 환경은 64비트 Windows 10 버전 1809(빌드 17763) 이상입니다.
- 제공되는 Windows 설치 파일 이름은 `NetOpsSuite-setup-1.0.11.exe`입니다.
- v1.0.10 등 이전 버전의 기본 Program Files 설치 위에 실행하면 앱 번들이 자동으로 교체됩니다. 실행 중인 NetOps Suite를 먼저 종료하고 중요한 사용자 프로파일은 별도로 백업하는 것을 권장합니다.
- `_internal`은 앱 전용 폴더이므로 사용자가 직접 넣은 파일은 업데이트 성공 시 제거될 수 있습니다. 사용자 파일은 `%LOCALAPPDATA%\NetOps Suite` 또는 별도 문서 폴더에 보관하세요.
- Program Files 밖의 사용자 지정 설치에서는 자동 정리를 건너뛰므로 불필요한 파일이 남을 수 있습니다. 설치 폴더 전체를 수동 재귀 삭제하지 말고 공식 제거·재설치 절차를 사용하세요.
- 코드 서명 인증서가 구성되지 않은 경우에는 명시적으로 승인된 무서명 릴리스로만 게시되며, Windows에서 확인된 게시자 정보가 표시되지 않을 수 있습니다.

## 검증 및 무결성

- 설치 정리 계약 테스트는 삭제 범위, AppId·설치 경로·버전 검증, Program Files 제한, 재분석 지점 검사, 백업·복구와 성공 후 커밋 조건을 확인합니다.
- 가이드 생성·검증, 정적 검사, 전체 자동화 테스트, Python 컴파일 및 패키징 실행 검사를 릴리스 워크플로에서 수행합니다.
- 공개 전 Git 히스토리와 작업 트리를 대상으로 비밀정보 검사를 수행하며, 실패하면 게시 단계로 진행하지 않습니다.
- CI가 정상 완료되면 설치 파일과 함께 `SHA256SUMS.txt` 및 CycloneDX 형식의 `python-dependencies.cdx.json`을 게시합니다. 실제 체크섬과 서명 상태는 게시된 자산과 워크플로 결과에서 확인하세요.
