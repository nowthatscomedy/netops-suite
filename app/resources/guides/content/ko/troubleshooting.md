# 문제 해결 가이드

## 목적 {#troubleshooting}

NetOps Suite가 시작되지 않거나 화면 조회·저장·외부 도구·네트워크 작업이 실패할 때, 원인을 안전하게 좁히는 공통 순서를 제공합니다.

## 사전 준비 및 권한

- 오류 메시지 전문, 발생 시각, 선택 화면, 입력 종류와 재현 단계를 기록합니다. 실제 비밀번호와 토큰은 기록에서 제거합니다.
- `보기 > 애플리케이션 로그`와 현재 로그 폴더의 `app.log`를 확인할 수 있어야 합니다.
- 관리자 권한 문제를 조사하더라도 먼저 일반 권한에서 읽기 전용 확인을 수행합니다.
- 네트워크·외부 서비스 문제는 조직의 프록시, 방화벽, DNS, 인증서 검사 정책을 확인할 담당자와 협업합니다.

## 입력 및 선택 사항

문제를 보고할 때 다음 정보를 준비합니다.

- `설정 > 프로그램`의 앱 버전
- Windows 버전과 일반/관리자 실행 여부
- `설정 > 저장 위치`의 적용 경로
- `설정 > 도구 연동`의 iperf3·OUI 상태
- 오류가 난 기능, 대상 유형, 포트와 실행 모드
- 오류 전 마지막 정상 동작과 최근 변경 사항

민감한 실제 주소는 보고서에서 `192.0.2.x`, 실제 호스트는 `device.example.test`, 계정은 `example-operator`처럼 대체합니다.

## 사용 방법

### 공통 진단 순서

1. 오류 창과 화면 상태를 그대로 기록합니다.
2. 실행 중 작업이 있으면 기능의 `중지`를 한 번 누르고 안전한 종료를 기다립니다.
3. `보기 > 애플리케이션 로그`에서 같은 시각의 첫 오류를 찾습니다.
4. 입력 철자, 경로 존재, 대상 선택, 포트·프리픽스 범위와 필수값을 확인합니다.
5. 해당 화면의 `새로고침`, `목록`, `상태 확인`을 한 번 실행합니다.
6. 설정·화면 상태 문제면 앱을 정상 종료하고 다시 실행합니다.
7. 관리자 필수 작업만 관리자 권한으로 재시도합니다.
8. 동일 오류가 재현되면 앱 버전, 로그와 최소 재현 단계를 함께 보고합니다.

### 앱이 시작되지 않음

- 설치본은 `%LOCALAPPDATA%\NetOps Suite\logs\app.log`, 설치 없이 실행한 경우 프로그램 폴더의 `data\logs\app.log`와 Windows 이벤트를 확인합니다.
- 소스 환경은 `.venv\Scripts\python.exe`가 있는지 확인하고 없으면 `.\scripts\install_dev.ps1`을 실행합니다.
- `run_netops_suite.bat`의 오류 코드를 기록합니다.
- 보안 프로그램이 실행 파일이나 의존성을 격리했는지 조직 절차로 확인합니다.

### 화면이 비거나 버튼이 비활성화됨

- 대상 행·프로파일·파일이 선택됐는지 확인합니다.
- 내 PC의 IP 변경은 관리자 권한과 어댑터 선택이 모두 필요합니다.
- Ping/TCPing/전송의 `중지` 버튼이 활성화되어 있으면 이전 작업이 아직 끝나는 중일 수 있습니다.
- Wi-Fi는 어댑터와 WLAN 서비스, 장비 점검·백업은 Excel 검증, 설정 명령 만들기는 프로파일과 장비 행을 먼저 확인합니다.

### 저장 또는 폴더 열기 실패

- `설정 > 저장 위치`에서 존재하는 절대 폴더인지 확인합니다.
- 파일이 Excel·편집기·동기화 프로그램에 잠겨 있는지 확인합니다.
- 다른 이름으로 쓰기 가능한 로컬 폴더에 저장해 권한 문제를 구분합니다.
- 로그 폴더 변경은 앱 재시작 후 적용됨을 확인합니다.

### 네트워크 진단 실패

- 먼저 로컬 인터페이스, IP·프리픽스, 게이트웨이와 DNS를 확인합니다.
- Ping, TCPing, DNS, 경로 추적을 조합해 ICMP 차단과 서비스 포트 장애를 구분합니다.
- ARP는 같은 로컬 대역에서만 기대한 결과를 낼 수 있습니다.
- 외부 조회만 실패하면 프록시·방화벽·DNS·인증서 검사 정책을 확인합니다.

### 외부 도구 실패

- `설정 > 도구 연동 > 전체 상태 새로고침`을 실행합니다.
- iperf3의 실제 사용 경로와 버전을 확인합니다.
- 권한 우회로 문제를 해결하려 하지 말고 실행 파일·설치·정책 원인을 수정합니다.

## 성공 확인

- 동일한 최소 입력으로 오류가 더 이상 재현되지 않습니다.
- 화면 상태와 `app.log`에 성공 또는 명확한 정상 완료 메시지가 표시됩니다.
- 저장 문제는 새 파일을 다시 열어 내용까지 확인합니다.
- 네트워크 문제는 서로 다른 두 진단 결과가 기대와 일치합니다. 예를 들어 DNS 결과와 대상 포트 TCPing을 함께 확인합니다.
- 설정 변경 문제는 앱 재시작 후 현재 적용 경로와 값이 유지됩니다.

## 결과 및 저장 위치

- 앱 로그는 현재 로그 폴더의 `app.log`입니다.
- 진단 CSV/TXT/로그는 기본 결과/내보내기 폴더 또는 사용자가 선택한 경로에 있습니다.
- 장비 점검 상세 산출물은 결과 폴더(기본값은 데이터 폴더의 `results`)에 있습니다.
- 문제 보고용 사본은 비밀번호·토큰·개인 키·내부 주소를 제거한 뒤 승인된 경로에 저장합니다.

## 주의사항

- 문제 재현을 위해 운영망 스캔 범위, 동시성, Timeout 또는 권한을 무분별하게 높이지 마세요.
- DNS 캐시 비우기, IP 변경, 설정 초기화, 원격 파일 삭제는 진단이 아니라 상태 변경입니다. 필요한 증거를 먼저 보존합니다.
- `모든 설정 초기화`는 마지막 수단이며 로그·결과를 삭제하지 않고 Windows·원격 장비 변경을 되돌리지 않습니다.
- 오류 로그를 외부에 공유할 때 내부 주소, 사용자명, 파일 경로, 명령 출력과 장비 구성을 가립니다.

## 문제 해결

- 같은 오류가 세 번 이상 재현되면 더 큰 권한이나 범위로 반복하지 말고 최소 재현 단계와 로그를 담당자에게 전달합니다.
- 로그가 만들어지지 않으면 현재 로그 경로와 쓰기 권한, 앱이 비정상 종료됐는지 확인합니다.
- 설정이 손상됐다고 의심되면 먼저 설정 폴더를 백업하고 `설정 파일 다시 불러오기`를 사용합니다. 초기화 전 백업 없이 파일을 삭제하지 마세요.
- 업데이트 후에만 문제가 생기면 현재 버전, 이전 정상 버전, 릴리스 정보와 재현 단계를 기록해 보고합니다.

## 문제 해결 빠른 안내 {#quick-troubleshooting}

오류의 원인과 다음 조치를 찾습니다.

**준비**: 실패한 화면·작업·오류 문구를 확인합니다.

1. 입력값과 대상 선택을 다시 확인합니다.
2. 필요한 권한·네트워크·외부 도구 상태를 확인합니다.
3. 문제가 반복되면 해당 작업 로그와 앱 로그를 비교합니다.

**성공 확인**: 문제의 범위를 확인하고 수정 후 해당 작업을 다시 검증합니다.

**안 되면**: 로그를 전달하기 전 주소·계정·설정 등 민감 정보를 검토합니다.
