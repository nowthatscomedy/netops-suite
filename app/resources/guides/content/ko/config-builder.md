# 설정 명령 만들기 가이드

## 목적 {#config-builder}

YAML 프로파일의 변수·검증 규칙·Jinja2 명령 블록과 CSV/XLSX 장비 값을 결합해 장비별 CLI를 미리 보고 저장합니다. 이 기능은 CLI 텍스트를 생성할 뿐 장비에 직접 접속하거나 설정을 적용하지 않습니다.

![설정 명령 만들기 화면](assets/generated/config-builder-overview.png)

## 사전 준비 및 권한

- NetOps Suite 통합 앱의 왼쪽 메뉴에서 `설정 명령 만들기`를 엽니다. 예전 독립 실행 스크립트 안내는 현재 통합 앱 실행 방법이 아닙니다.
- 설치본은 시작 메뉴의 NetOps Suite를 사용합니다. 소스 환경은 프로젝트 루트에서 `.\scripts\run_dev.ps1`을 실행합니다.
- 처음에는 내장 샘플 프로파일과 장비 값을 사용하고, 운영용 프로파일은 장비 모델·OS·버전에 맞게 검토합니다.
- 생성 CLI를 장비에 붙여넣을 권한과 변경 절차는 앱 밖에서 별도로 승인받아야 합니다.

## 입력 및 선택 사항

- 프로파일: YAML 파일이며 고유 `id`, 제조사, 모델, 펌웨어, 변수 정의와 명령 블록을 가집니다.
- 장비 값: CSV 또는 XLSX이며 `profile_id` 열이 필수입니다. `device_id`는 식별 편의를 위한 선택 열입니다.
- 각 프로파일 변수는 필수 여부, 기본값, 자료형과 `suffix_number` 또는 `ipv4` 연속 값 규칙을 가질 수 있습니다.
- 명령 블록은 화면에서 켜거나 꺼 전체 장비 렌더링에 반영합니다.
- 비밀로 판단되는 열 이름(`secret`, `password`, `community`, `passphrase`, `token`, `key`)은 일부 안내에서 마스킹되지만 원본 파일과 생성 CLI에는 실제 값이 남을 수 있습니다.

샘플 데이터가 필요하면 다음 내장 예시를 사용할 수 있습니다.

- 프로파일: `sample_comprehensive_reference.yaml`
- 장비 값: `sample_comprehensive_reference_devices.csv`

## 사용 방법

### 샘플로 첫 CLI 만들기

1. `설정 명령 만들기`를 열고 `1. 기준 프로파일`을 고른 뒤 `샘플로 시작`을 누릅니다. 내장 예시가 있는 프로파일은 그 예시를, 직접 만든 프로파일은 변수 종류에 맞는 예시 값으로 장비 2대를 자동으로 채웁니다.
2. `2. 장비 값 입력` 표에 불러온 장비 행을 확인합니다. 한 행이 장비 한 대입니다.
3. 장비 행 하나를 선택합니다.
4. `이슈`에 오류가 없는지 확인합니다. 변수 설명이 필요하면 오른쪽 `안내`와 변수 요약을 엽니다.
5. 오른쪽 `3. 만들어진 CLI 확인·복사`와 기본으로 열리는 `CLI` 탭에서 생성 결과를 확인합니다.
6. `복사`로 현재 장비 CLI를 클립보드에 복사하거나 `복사+다음`으로 다음 행까지 순서대로 작업합니다.
7. 실제 적용을 별도 절차에서 완료한 뒤에만 `작업 상태 관리`를 펼쳐 `적용 완료로 표시`로 상태를 기록합니다. 이 버튼 자체가 장비에 CLI를 전송하지는 않습니다.

### 필요한 고급 기능 열기

기본 화면에서 파일·장비 행·값 입력·명령 미리보기·복사·CLI 저장까지 진행할 수 있습니다. 프로파일 생성과 관리는 화면 상단의 `프로파일 만들기·관리`에서 시작합니다. `고급 작업`에서는 명령 블록 선택, 행 필터, 행 복사 및 삭제, 표시 컬럼, 파일 및 저장 옵션을 각각 펼쳐 사용합니다. 각 구역을 닫아도 입력과 선택은 유지됩니다. 필터나 저장 옵션을 변경했다면 고급 작업 버튼의 `변경된 옵션 N개` 표시로 확인할 수 있습니다.

상단 카드의 첫 줄에서는 기준 프로파일과 샘플을 선택하고, 다음 줄에서는 장비 파일 열기·빈 행 추가·고급 작업을 사용합니다. 작은 창에서 고급 기능을 펼친 경우 고급 영역과 오른쪽 CLI 영역을 각각 스크롤해 사용할 수 있습니다.

### 장비 값 파일 열기와 편집

1. `장비 변수 파일 열기` 또는 `데이터 열기`에서 `.csv`나 `.xlsx`를 선택합니다.
2. 각 행의 `profile_id`가 실제 프로파일 ID와 맞는지 확인합니다.
3. 표에서 hostname, 관리 IP, 마스크, 게이트웨이, VLAN 등 필요한 값을 수정합니다.
4. `이슈` 탭에서 필수값 누락, 형식 오류, 중복 hostname/IP, 게이트웨이 대역 불일치를 해결합니다.
5. 특정 장비를 찾을 때는 필터 열과 값을 사용하고, 표시 컬럼·고정 기능으로 작업 열을 정리합니다.
6. 명령 블록 선택을 바꾸면 해당 블록이 전체 CLI에서 포함 또는 제외됩니다.

### 행 복사와 연속 값

- `선택 행 복사`는 값을 그대로 복제하므로 hostname과 IP처럼 고유해야 하는 값은 직접 바꿉니다.
- `연속 값 복사`는 프로파일에서 `auto_increment`가 지정된 변수만 증가시킵니다.
- `device_id`는 자동 증가 규칙이 정의되지 않았다면 직접 고유하게 수정합니다.

### 프로파일 작성

`전체 창`은 현재 편집 중인 표를 그대로 큰 창으로 옮깁니다. 전체 창에서 바꾼 입력도 같은 문서에 남으며, 창을 닫으면 원래 화면으로 돌아옵니다. 창을 열거나 닫는 동작 자체는 파일을 저장하지 않습니다.

1. 화면 상단 오른쪽의 `프로파일 만들기·관리`를 누르고 `새 프로파일`, `프로파일 복사`, `프로파일 편집` 중 하나를 선택합니다. 전체 창에서도 같은 상단 버튼을 사용합니다. 편집·복사·삭제의 대상은 메뉴에 표시된 현재 `기준 프로파일`입니다. 프로파일을 선택하지 않았다면 `새 프로파일`로 만들 수 있습니다.
2. 프로파일 ID, 제조사·모델·펌웨어와 설명을 입력합니다.
3. 변수 이름, 자료형, 필수값, 기본값, 연속 값 규칙을 정의합니다.
4. 명령 블록에 `hostname {{ hostname }}`처럼 변수를 참조하는 CLI 줄을 작성합니다.
5. `검토/저장`에서 YAML 파싱, 프로파일 구조, Jinja 문법·정의되지 않은 변수와 합성 샘플 CLI 렌더 결과를 확인합니다.
6. 위험 명령 경고와 저장 대상 파일을 확인하고 저장합니다.
7. 장비 값 파일의 `profile_id`와 새 프로파일 ID를 일치시켜 렌더링합니다.

같은 메뉴의 `프로파일 삭제`는 대상 파일과 현재 참조 중인 장비 행을 확인한 뒤 승인해야 삭제합니다. `새로고침`은 프로파일 목록을 다시 읽습니다. 메뉴를 열거나 작성·편집 창을 취소하는 것만으로 장비 값이나 프로파일 파일을 저장하지 않습니다.

### 저장과 내보내기

- 장비 값 파일은 `고급 작업 > 파일 및 저장 옵션 > 다른 이름으로 저장`으로 CSV/XLSX에 저장합니다. CLI 명령 저장과 별개입니다.
- `실시간 파일 저장`은 열린 원본 파일에 편집 내용을 반영합니다. 오류 행이 있으면 기본적으로 자동 저장을 보류합니다.
- `오류 있어도 실시간 저장`은 오류를 포함한 파일 저장이 꼭 필요할 때만 켭니다.
- 기본 화면과 전체 창 모두 명령 영역의 `CLI 저장`에서 저장 형식을 선택합니다.
- `선택 장비 CLI 저장`: 현재 선택한 장비의 명령을 TXT로 저장합니다. 선택 장비의 명령을 생성할 수 있을 때 활성화됩니다.
- `전체 CLI 묶음 저장`: 현재 생성 가능한 장비 명령을 하나의 TXT로 저장합니다.
- `장비별 CLI ZIP 저장`: 현재 생성 가능한 장비마다 TXT를 만들고 ZIP으로 묶습니다.
- 생성 가능한 명령이 하나도 없으면 `CLI 저장`을 사용할 수 없습니다. 일부 행만 생성 가능하면 전체 묶음과 ZIP에는 그 행만 포함되므로 대상 장비 수와 오류 행을 확인합니다. 화면의 행 필터는 전체 묶음·ZIP 저장 대상을 제한하지 않습니다.
- 저장 창에서 경로를 선택한 뒤 완료 메시지와 실제 파일 내용을 확인합니다.

## 성공 확인

- 장비 표에 기대한 행이 표시되고 선택 장비의 명령 미리보기를 확인할 수 있습니다.
- 선택 장비 상태가 `복사 가능`이고 오류 수가 0입니다.
- CLI 미리보기의 모든 `{{ ... }}`가 실제 값으로 치환됐고 불필요한 블록이 제외됐습니다.
- hostname, 관리 IP, VLAN, 인터페이스와 기본값을 원본 설계 문서와 대조합니다.
- 내보낸 TXT 또는 ZIP을 다시 열어 장비별 구분과 줄바꿈, 문자 인코딩을 확인합니다.

## 결과 및 저장 위치

- 사용자 프로파일은 데이터 폴더의 `config_builder\profiles` 아래에 준비됩니다. 처음 실행 시 번들 샘플이 사용자 프로파일 폴더에 복사될 수 있습니다.
- 기존 프로파일 편집은 원본 YAML 파일명을 유지합니다. 대소문자를 무시했을 때 같은 ID나 파일명인 다른 프로파일이 있으면 저장을 차단합니다.
- 기존 파일을 바꾸는 경우 덮어쓰기 확인 후 `.bak` 복구 사본을 만들고 임시 파일을 원자적으로 교체한 다음 다시 읽어 검증합니다. 검증 실패 시 기존 파일로 복구합니다.
- 샘플로 시작한 장비 값은 데이터 루트의 `config_builder\device_values` 아래에 준비될 수 있습니다.
- CLI 저장 대화상자의 기본 제안 위치는 현재 결과/내보내기 폴더이며 최종 위치는 사용자가 선택합니다.
- 기존 장비 값 파일을 저장할 때 프로그램이 백업 사본을 만들 수 있지만, 운영 원본의 별도 버전 관리와 백업을 대신하지 않습니다.
- 정확한 현재 결과/내보내기 경로는 `설정 > 저장 위치`에서 확인합니다.

## 주의사항

- 내장 샘플은 데이터 구조와 화면 사용법을 보여주는 참고 자료이며 운영 명령의 정답이 아닙니다.
- 생성 성공은 CLI의 업무 적합성, 장비 호환성 또는 변경 안전성을 보장하지 않습니다.
- 실시간 저장은 열린 장비 파일을 직접 변경합니다. 샘플이나 원본을 보존하려면 먼저 별도 파일로 저장하세요.
- `오류 있어도 실시간 저장`을 켜면 불완전한 값이 파일에 남습니다.
- 비밀값이 있는 장비 파일, CLI, ZIP과 클립보드 내용은 운영 민감 자료로 취급합니다.
- 블록 선택은 현재 렌더링 전체에 영향을 줄 수 있으므로 내보내기 직전에 다시 확인합니다.
- `적용 완료로 표시` 상태는 작업 추적 표시일 뿐 장비의 실제 상태를 검증하지 않습니다.

## 문제 해결

- 프로파일을 찾지 못하면 `profile_id`의 공백과 철자, 프로파일 저장 여부를 확인하고 `새로고침`합니다.
- CLI가 비어 있으면 선택 장비의 `이슈`와 필수 변수, 선택된 명령 블록을 확인합니다.
- 자료형 오류는 IPv4, 정수, bool 등 프로파일이 요구하는 형식으로 값을 수정합니다.
- 중복 경고는 hostname 또는 IP가 다른 행과 겹치는지 확인합니다.
- 게이트웨이 경고는 관리 IP·마스크·게이트웨이가 같은 네트워크인지 확인합니다.
- 실시간 저장이 되지 않으면 파일이 읽기 전용인지, 다른 프로그램이 잠갔는지, 오류 행 때문에 보류됐는지 확인합니다.
- 프로파일 수정 후 결과가 그대로면 프로파일 목록을 새로고침하고 장비 행을 다시 선택합니다.
- 프로파일 저장이 충돌로 차단되면 같은 ID나 파일명이 대소문자만 다르게 이미 있는지 확인합니다. 기존 프로파일 수정이라면 새 파일명으로 저장하지 말고 원본 항목을 다시 열어 편집합니다.

## 설정 명령 만들기 빠른 안내 {#quick-config-builder}

장비에 사용할 설정 명령을 미리 만듭니다.

**준비**: 처음에는 샘플을 사용합니다. 실제 사용은 모델에 맞는 프로파일을 준비합니다.

1. 샘플로 시작 또는 장비 값 파일 열기를 누릅니다.
2. 장비 행을 선택하고 필요한 값을 입력합니다.
3. 오류를 해결한 뒤 명령 미리보기를 확인합니다.
4. 검토한 명령을 복사하거나 CLI 저장에서 선택 장비 TXT·전체 묶음 TXT·장비별 ZIP 중 하나를 고릅니다.

**성공 확인**: 장비별 명령이 표시됩니다. 이 기능은 장비에 자동 적용하지 않습니다.

**안 되면**: CLI 저장이 비활성화되어 있으면 프로파일과 필수값 오류를 해결합니다. 선택 장비 저장에는 명령을 생성할 수 있는 행을 선택해야 합니다. 전체 저장에는 생성 가능한 행만 포함됩니다.
