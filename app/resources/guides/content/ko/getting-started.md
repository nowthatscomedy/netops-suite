# NetOps Suite 빠른 시작

## 목적 {#overview}

NetOps Suite는 Windows 네트워크 운영 작업을 한 프로그램에서 처리하는 도구입니다. 네트워크 설정, 연결 진단, Wi-Fi 분석, 파일 전송, 장비 점검·백업, CLI 설정 생성, Codex CLI 기반 NetOps 어시스턴트를 왼쪽 메뉴에서 전환해 사용할 수 있습니다.

처음 사용하는 경우에는 실제 장비나 운영망을 변경하기 전에 다음 순서로 익히는 것이 안전합니다.

1. `연결 진단`에서 예약 예시 주소로 입력 형식을 확인합니다.
2. `CLI 설정 생성`에서 내장 샘플로 CLI를 미리 봅니다.
3. `장비 점검/백업`에서 `샘플 생성`과 `먼저 검증`까지만 실행합니다.
4. 저장 위치와 결과 파일에 민감한 정보가 포함될 수 있음을 확인합니다.

## 사전 준비 및 권한

- 지원 환경은 64비트 Windows 10 버전 1809(빌드 17763) 이상입니다.
- 조회, Ping, TCPing, DNS 조회, 경로 추적, Wi-Fi 스캔, CLI 생성은 일반 권한에서 대부분 사용할 수 있습니다.
- DHCP·고정 IP·게이트웨이·DNS 변경과 일부 DNS 캐시 작업은 관리자 권한이 필요합니다.
- `iperf3`, Codex CLI처럼 별도 실행 파일이 필요한 기능은 `설정 > 도구 연동`에서 상태를 먼저 확인합니다.
- Codex 로그인 화면이나 브라우저가 열리면 계정 선택, 동의와 MFA는 사용자가 직접 완료합니다. NetOps Suite는 Codex 로그인 자격 정보나 인증 캐시를 읽거나 저장하지 않습니다.
- 운영 장비에 접속하는 기능은 승인된 테스트 계정과 변경 창구를 준비한 뒤 사용합니다.

## 입력 및 선택 사항

첫 학습에는 실환경 주소나 자격 증명 대신 다음과 같은 문서용 값을 사용합니다.

| 용도 | 안전한 예시 |
| --- | --- |
| IPv4 호스트 | `192.0.2.10` |
| IPv4 게이트웨이 | `192.0.2.1` |
| IPv4 서브넷 | `192.0.2.0/24` |
| 호스트 이름 | `router.example.test` |
| 사용자명 | `example-operator` |
| 비밀번호 자리표시자 | `CHANGE_ME_PASSWORD` |

`192.0.2.0/24`와 `.example.test`는 문서 예시용입니다. 실제 연결 시험이 필요할 때만 조직에서 승인한 대상 값으로 바꾸세요.

## 사용 방법

1. NetOps Suite를 실행합니다.
2. 왼쪽 메뉴에서 작업 화면을 선택합니다.
   - `네트워크 설정`: 어댑터 조회, DHCP/수동 IP, IP 프로파일
   - `연결 진단`: Ping, TCPing, DNS, 경로 추적, iperf3, ARP, 서브넷, OUI, 파일 전송, 명령 출력
   - `Wi-Fi 분석`: 현재 연결과 주변 AP·채널 분석
   - `장비 점검/백업`: Excel 장비 목록 기반 점검·백업·사용자 명령
   - `CLI 설정 생성`: YAML 프로파일과 CSV/XLSX 장비 값으로 CLI 렌더링
   - `NetOps 어시스턴트`: Codex CLI 대화와 정책 기반 NetOps 도구 실행
   - `설정`: 업데이트, 저장 위치, 외부 도구, 설정 초기화
3. 화면 위쪽의 작업 흐름 안내를 읽고 입력값을 채웁니다.
4. `검토`, `검증`, `확인` 단계가 제공되는 기능은 실행보다 먼저 사용합니다.
5. 변경 또는 외부 연결 경고가 표시되면 대상·영향·저장 위치를 다시 확인합니다.
6. 실행 후 상태 표시, 결과 표, 실시간 로그를 함께 확인합니다.
7. 필요한 결과만 `CSV 저장`, `TXT 저장`, `로그 저장` 또는 기능별 내보내기로 보관합니다.

## 성공 확인

- 왼쪽 메뉴에서 7개 주요 화면을 모두 열 수 있습니다.
- 하단 상태 표시줄에 `준비` 또는 선택 화면의 정상 상태가 표시됩니다.
- `연결 진단 > 서브넷 계산기`에서 `192.0.2.10`과 `24`를 입력하면 네트워크 주소 `192.0.2.0/24`가 계산됩니다. 이 계산은 네트워크 패킷을 보내지 않습니다.
- `CLI 설정 생성 > 샘플로 시작`에서 장비 행과 CLI 미리보기가 표시됩니다.

## 결과 및 저장 위치

- 설치본의 기본 데이터 루트는 `%LOCALAPPDATA%\NetOps Suite`입니다.
- 기본 설정 폴더는 데이터 루트 아래 `config`, 로그 폴더는 `logs`, 결과/내보내기 폴더는 `logs\exports`입니다.
- 정확한 현재 경로는 `설정 > 저장 위치 > 현재 적용 중인 위치`에서 확인합니다.
- 수동 저장 창에서는 사용자가 선택한 경로가 최종 저장 위치입니다.
- 개발 실행에서 `scripts\run_dev.ps1 -UseProjectData`를 사용하면 프로젝트의 `config`, `logs`, `inspector`, `config_builder` 경로를 사용합니다.

## 주의사항

- 네트워크 설정 적용, DNS 캐시 비우기, 원격 파일 삭제, 임시 서버 공개, 장비 사용자 명령은 운영 상태를 바꿀 수 있습니다.
- `0.0.0.0`에 임시 서버를 열면 모든 네트워크 인터페이스에서 접속을 받습니다. 필요한 인터페이스 IP로 제한하는 편이 안전합니다.
- 결과 Excel, 설정 백업, 세션 로그, raw command output, 생성 CLI, AI 대화 내보내기에는 내부 주소·명령·파일 경로·자격 정보가 포함될 수 있습니다.
- 예제 프로파일은 구조 참고용입니다. 장비 모델과 OS 버전을 확인하지 않은 채 운영 장비에 그대로 적용하지 마세요.
- 관리자 권한은 필요한 작업을 할 때만 사용하고, 작업 후 일반 권한으로 다시 실행하세요.

## 문제 해결

- 화면이 비어 있으면 해당 화면의 `새로고침`, `목록`, `스캔` 버튼을 먼저 누릅니다.
- 네트워크 설정 버튼이 비활성화되어 있으면 왼쪽 아래 `관리자`를 눌러 승인 후 다시 실행합니다.
- 외부 도구를 찾지 못하면 `설정 > 도구 연동 > 전체 상태 새로고침`을 실행합니다.
- Codex CLI를 찾지 못하면 조직이 승인한 공식 방법으로 설치한 뒤 `설정 > 도구 연동`에서 자동 감지를 다시 실행하거나 실제 실행 파일 경로를 저장합니다. 로그인이 필요하면 `NetOps 어시스턴트 > 연결 설정 > 로그인`을 사용합니다.
- 저장에 실패하면 `설정 > 저장 위치`에서 경로가 존재하는 절대 폴더인지, 쓰기 권한이 있는지 확인합니다.
- 앱 동작을 진단할 때는 `보기 > 애플리케이션 로그`와 현재 로그 폴더의 `app.log`를 확인합니다.
- 문제가 계속되면 [문제 해결](troubleshooting.md)에서 증상별 점검 순서를 확인합니다.
